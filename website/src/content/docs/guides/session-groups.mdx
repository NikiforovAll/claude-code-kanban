By default, the sidebar puts each session under its project. A group lets you keep related work together when it spans more than one folder. For example, you can keep a backend repo and a frontend repo together when you change both for the same feature.

A group can hold whole projects and single sessions. Groups show in a **Groups** section above the **Projects** section. In the **All sessions** view, the section below the groups is called **Sessions**.

## Create a group

Use one of these methods:

- Drag a session or a project onto another session or project that is not in a group. Claude Code Kanban makes a new group that holds both.
- Right-click a session card or a project header and choose **+ New group…**. On a touch screen, press and hold for about half a second to open the same menu. With the keyboard, move the sidebar cursor to the item and press <kbd>Shift+F10</kbd> or the <kbd>Menu</kbd> key.

The name field of the new group opens in place. Type a name and press <kbd>Enter</kbd>.

The same menu also lists your other groups, so you can move an item to one of them. If the item is already in a group, the menu has a **Remove from** entry for that group.

## Manage a group

The group header has these controls:

- **Scratchpad** opens a note for the group. See [Session log and details](/claude-code-kanban/guides/session-details/).
- **Rename** (pencil icon) opens the name field in place.
- **Delete** (the × button) removes the group after you confirm. Its sessions and projects go back to **Projects**.

To change the order of groups, drag a group header onto another group header.

To take an item out of a group, drag it onto the **Projects** or **Sessions** section label.

A group with no items shows the hint "Drop a session or a project here". When a filter is on, an empty group does not show.

## Where groups are saved

The server saves your groups in `<config-dir>/.cck/groups.json`, so every browser and window on the board shows the same groups, and a change in one shows in the others at once. Each Claude config dir has its own groups, so groups you make for one config dir do not show for another.

Older versions kept groups in the browser's local storage, under the key `sessionGroups`. The first board that loads after the upgrade moves its groups to the server one time and then sets the `groupsMigratedAt` key, so it does not move them again. A browser that loads later shows the server's groups; its own older groups stay in `sessionGroups` but do not show.

Groups hold references to sessions and projects. A session that the sidebar filter hides stays in its group.

## Groups from dispatch

When a session starts another session with `dispatch start --group <name>`, the board shows a temporary group with that name. The name must be kebab-case and 64 characters or fewer, for example `site-docs`. See [Dispatch tasks to other sessions](/claude-code-kanban/guides/dispatch/).

A temporary group works like this:

- It holds the started sessions. The starting session stays where it is.
- The server saves it in `<config-dir>/.cck/dispatch-groups.json`, so it is not stored in the browser.
- It stays while the Claude process of any member runs, and for 60 seconds after the last one stops.
- After that, only pinned members stay in the group. The other sessions go back to their project block. Because pinned members stay, a group with a pinned session is still there after a server restart.

A temporary group header has a **Keep** button and no rename or delete controls. **Keep** makes a named group with the same name and the same sessions. Later dispatches with that `--group` name go into the named group.

If a named group already has the same name as a temporary group, the named group takes its sessions.

### Where a started session goes

Claude Code Kanban picks the place for a started session when it starts, so the card does not move after it shows. A session started with `--group` goes to that group. A session started without it goes to its project block, even when the starting session is in a group.

Until the first transcript line arrives, the board shows a "starting" placeholder card in that place.

A session or project that you put in a named group stays there. A dispatch group does not move it.
